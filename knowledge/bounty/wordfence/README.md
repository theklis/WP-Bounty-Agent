# Wordfence program intelligence

Read the [dated snapshot](snapshot-2026-09-19.md) for the rules observed on 2026-09-19, then recheck the linked official pages before a consequential decision. Use the [scope assessment template](../../../templates/wordfence-scope-assessment.md) for a particular finding. The [current-intelligence convention](../../../docs/current-intelligence.md) controls freshness and contradictions. This area does not determine whether the technical vulnerability exists.

For each target, establish the exact plugin/theme and version, local versus vendor-hosted component, repository/premium status, current availability, installations or justified sales estimate, vulnerability category and actual attacker privilege, researcher tier if known, exclusions, and any verified active promotion. Compare every required condition with an official source. If tier is unknown, show the outcomes by tier rather than assigning one. Treat Wordfence's estimator or program response as a current check, not a substitute for a technical finding.

Use **LIKELY IN SCOPE**, **LIKELY OUT OF SCOPE**, **TIER-DEPENDENT**, **CONDITION-DEPENDENT**, **RECHECK REQUIRED**, or **UNKNOWN**. These are provisional research assessments, not Wordfence decisions. A finding can be tier-dependent **and** require rechecking for an ambiguous exclusion; show both conditions. Classify the demonstrated effect, not just a generic weakness label. Cite the rule and verification date, list missing conditions, and recheck immediately before submission. Check reward schedules or the official estimator at the time; this repository makes no payout prediction.
