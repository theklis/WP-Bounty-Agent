# WooCommerce security model for extension review

WooCommerce adds customers, shop managers, products, carts, orders, payment states, and webhooks to a WordPress site. Extensions may add vendors, bookings, subscriptions, custom order fields, or payment rules. Start with the target extension's actual business workflow; do not assume one WooCommerce version, checkout setting, or storage mode. [Sources: [roles and capabilities](https://woocommerce.com/document/roles-capabilities/), [orders](https://developer.woocommerce.com/docs/features/orders/)].

## Actors and objects

A customer account, guest checkout, shop manager, and administrator have different relationships to an order. `manage_woocommerce` or order-management capabilities may authorize store staff actions; they do not define every extension-specific permission. Trace **guest → cart/session → customer or guest order → payment → merchant/admin**. For each transition, identify who controls prices, coupons, addresses, line items, order status, customer ID, and external payment result. A cart value or posted order ID is not trusted just because WooCommerce later persists it. [Source: [WooCommerce roles](https://woocommerce.com/document/roles-capabilities/)].

Checkout and My Account endpoints include paying for an order, viewing an order, editing account details, and managing payment methods. An extension may hook into these paths or expose similar custom endpoints; trace the exact selected order/account and actor rather than assuming that a My Account URL enforces ownership for the extension. Cart/session state can outlive the request that created it and can be consumed by checkout or deferred callbacks. [Source: [WooCommerce endpoints](https://developer.woocommerce.com/docs/best-practices/urls-and-routing/woocommerce-endpoints)].

An order ID is an identifier, not an authorization secret. An order key or payment link may function as a bearer-like input in a specific flow, but never assume possession alone suffices: check the exact endpoint's additional login, customer, email, session, status, and expiry rules. Current WooCommerce documentation describes customer-linked pay links requiring the assigned customer's login, while some guest pay flows may request billing-email verification depending on session and order age. **These are version/configuration-sensitive behaviors**, not universal rules; verify the installed code and settings. [Source: [paying for customer and guest orders](https://woocommerce.com/document/managing-orders/view-edit-or-add-an-order/)].

## Storage and APIs

Use `wc_get_order()`/`wc_get_orders()` and order CRUD objects as the conceptual access layer when tracing extension code. High-Performance Order Storage (HPOS) can keep orders in dedicated tables rather than posts/postmeta; a plugin that assumes every order is a `shop_order` post may read stale or wrong data in some configurations. Query support and synchronization vary by WooCommerce version and active storage mode. **Version note:** WooCommerce documents HPOS as the default for new stores since **8.2**; inspect the target installation before reasoning from database layout. [Sources: [order queries](https://developer.woocommerce.com/docs/features/orders/wc-get-orders/), [HPOS queries](https://developer.woocommerce.com/docs/features/orders/high-performance-order-storage/wc-order-query-improvements/), [HPOS overview](https://developer.woocommerce.com/docs/features/orders/)].

An order getter or CRUD save does not perform the extension's business authorization. Trace which actor can choose the order and which state transition is allowed. Payment status may be updated by callbacks or webhooks after the original checkout request; review signature verification, event/order binding, duplicate delivery, and downstream fulfillment separately. WooCommerce webhooks have topic, destination URL, and optional secret/signature behavior; verify the installed implementation and configured secret. [Sources: [WooCommerce webhooks](https://developer.woocommerce.com/docs/best-practices/urls-and-routing/webhooks), [webhook API](https://developer.woocommerce.com/docs/apis/rest-api/v2/webhooks)].

**Trace next:** the customer/guest relationship to the exact order; where any order key or session value came from; who can modify payment/order state; whether the extension rechecks ownership at reads and writes; and whether background work or webhooks complete the chain. [Related: [ownership](ownership-and-plugin-models.md), [tokens](nonces-and-tokens.md), [background work](background-and-rendering.md)].
