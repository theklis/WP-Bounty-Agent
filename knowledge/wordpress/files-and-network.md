# Filesystem, outbound requests, and redirects

## Uploads, imports, and file actions

For each upload, trace **caller → submitted name/content → temporary file → type and extension checks → final path → web accessibility → possible execution or disclosure**. `wp_handle_upload()`/media helpers use core checks and filters; assess the actual call arguments, overrides, allowed MIME list, and plugin preprocessing. A browser-provided MIME field is not proof of file content. `wp_check_filetype_and_ext()` is relevant evidence but does not grant upload permission or guarantee a non-executable destination under every server configuration. An upload issue does not automatically imply code execution. [Sources: [media upload helper](https://developer.wordpress.org/reference/functions/media_handle_upload/), [`_wp_handle_upload()` core flow](https://developer.wordpress.org/reference/functions/_wp_handle_upload/), [`wp_check_filetype_and_ext()`](https://developer.wordpress.org/reference/functions/wp_check_filetype_and_ext/)].

Imports and ZIP extraction add archive entry names, destination paths, overwrite behavior, and post-extraction processing to the path. For reads, downloads, writes, and deletes, trace path normalization, base-directory containment, symlink handling where relevant, file ownership, and whether the resulting file is exposed to the web. A string prefix check may not settle canonical path containment. Check who may choose a file or record ID; filesystem safety and object authorization are independent. A generated export can expose another user's data even if no arbitrary file read exists. These are reasoning questions; behavior depends on the plugin's code and server configuration.

`WP_Filesystem` abstracts local writes across direct and credential-based transports; its successful initialization does not authorize the web caller to choose a path or content. Trace the selected transport, requested credentials, destination, and operation (`put_contents`, read, remove, or directory operations) separately. [Source: [WordPress Filesystem API](https://developer.wordpress.org/apis/filesystem/)].

## HTTP API, webhooks, and SSRF

`wp_remote_get()`/`wp_remote_post()` send outbound requests; the URL can be influenced by forms, options, webhooks, imported data, or a prior handler. Trace original URL, redirects, protocol, DNS/host validation, credentials/headers, response use, and whether an internal address is reachable from that server. WordPress provides `wp_safe_remote_get()` and `wp_safe_remote_post()` variants for arbitrary URLs that enable unsafe-URL rejection; validation policy and filters still need inspection in the target environment. A remote request call alone does not establish SSRF or impact. [Sources: [HTTP API](https://developer.wordpress.org/apis/making-http-requests/), [`wp_remote_post()`](https://developer.wordpress.org/reference/functions/wp_remote_post/), [`wp_safe_remote_get()`](https://developer.wordpress.org/reference/functions/wp_safe_remote_get/)].

For an inbound webhook, distinguish the claimed sender from a verified signature/secret, replay controls, object mapping, and the state transition triggered. For an outbound webhook, identify who can set the destination and what data/credential is included. A valid signature can authenticate a payload source without authorizing every object change encoded in the payload. WooCommerce-specific behavior is in [WooCommerce](woocommerce.md).

## Redirects

`wp_redirect()` sends a Location header and does not restrict it to the site's host. `wp_safe_redirect()` validates against allowed hosts and falls back when necessary; allowed-host filters and caller-supplied destinations still matter. Neither function exits automatically. Assess source of destination, intended off-site use, surrounding authentication flow, and downstream impact before claiming a security issue; an open redirect may be low impact on its own. [Sources: [`wp_redirect()`](https://developer.wordpress.org/reference/functions/wp_redirect/), [`wp_safe_redirect()`](https://developer.wordpress.org/reference/functions/wp_safe_redirect/)].
